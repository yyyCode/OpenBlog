# 设备指纹限流优化

> 网关限流从「纯 IP 过滤」升级为「设备指纹 + IP」复合识别。
> 日期：2026-08-31｜涉及：vue/ + OpenBlog-gateway（business/message 零改动）

## 背景

原限流仅按 IP 滑动窗口，四个缺陷：转发头可伪造、旋转代理换 IP 打穿、NAT 共享误伤合法用户、IPv6 地址轮换。

## 方案

**前端**：FingerprintJS 基于硬件信号（Canvas/WebGL/字体/音频）计算稳定指纹，无痕/清 Cookie 不失效；单例计算 + sessionStorage 缓存 + 300ms 超时降级，随请求透传 `X-Device-Fingerprint` 头。

**网关**：新增 `FP_IP` scope，限流 key = `gateway:rl:{指纹}_{IP}_{路径}`；非法/缺失指纹自动降级纯 IP，Redis 故障 fail-open 放行（绝不 500）。

**覆盖**：login / register / email-code / refresh / feedback 五个未登录敏感接口。

## 真实收益

- 共享 IP（NAT/公司网络）下不同设备各算各桶，**互不挤占配额**，降低误伤
- 限流从"按地址粗粒度"收敛为"按设备精粒度"

## 边界（诚实声明）

- **旋转代理 + 固定指纹仍能拿到每个 IP 的独立配额**（key 含 IP，指纹不跨 IP 累计）
- 指纹是客户端可控 header 值，不承诺对抗专业指纹伪造
- 若需对冲旋转代理，需再加一层**按指纹全局累计**的计数器（key 不带 IP）

## 简历表述

网关限流从纯 IP 过滤升级为「设备指纹 + IP」复合识别，FingerprintJS 计算稳定指纹随请求透传，非法/缺失指纹自动降级纯 IP、Redis 故障 fail-open 放行；复合 key 让共享 IP（NAT/公司网络）下不同设备各算各桶、互不挤占配额，限流从按地址收敛为按设备粒度，降低共享出口误伤。
